# 階段二：對手也能吃道具（規劃中，尚未排程）

- 日期：2026-11-01
- 狀態：**只是計畫，不要實作**。使用者 2026-11-01 決定先完成階段一（`feature/classic-pickup-density`），實際玩過之後再決定要不要做。
- 分支：`feature/rival-item-pickups`，從 `feature/classic-pickup-density` `caa14e7e` 開出，因為要沿用它的量測 bot 和版本鍵。開工前要先 merge 最新的 `develop`。

## 目標

在經典競速裡，讓對手也能拿光圈和地面道具，提高對手的威脅感和比賽的刺激性，**但不能讓玩家拿到的變少**。

## 設計原則

1. **道具會重生，不會被搶光。**
   - 被任何一台車吃掉的光圈或道具，2～3 秒後重生。
   - 或者改成「每台車各算一份」：對手吃了，玩家看到的那份仍然在。
   - 兩種做法在實作前要先比較，不管選哪一種，都要讓玩家在階段一量到的拿取量（每分鐘 NITRO、BOOST 開啟比例）**不下降**。
2. **跟難度連動。** 使用現有的 `difficulty` 設定，不新增設定項目。
   - Easy：對手不吃道具（等於現況）。
   - Normal：對手只吃路線上剛好經過的，不會刻意轉向去追。
   - Hard：對手會主動換車道或飛去吃。
3. **對手吃到的獎勵會用出來。** 吃到 nitro 光圈就累積 NITRO，照對手原本的個性時機放出來，沿用 `RIVAL_NITRO_CHARGES` 這套邏輯。上限仍然不能超過玩家的上限。
4. **跟追趕機制一起調。** 對手本來就有追趕機制（`RUBBER_BAND_MAX = 0.04`），再加上道具加成，可能會疊加過頭。需要用量測決定 Hard 難度要不要降低追趕機制的強度。
5. **看得出來、聽得出來。**
   - 對手吃到道具或放 NITRO 時，要有畫面提示，例如光圈閃一下、尾焰變亮。音效重用現有的提示音，對手的音量比玩家的小。
   - 不能只靠聲音提示；同一個瞬間有好幾台車吃到時，提示要節流，不能狂響。
6. **碰撞規則不變。** 對手去追道具時，仍然要遵守 CLAUDE.md 的「Solid obstacles and AI avoidance」和「Shared collision physics」，不能為了吃道具穿過障礙物或其他車。

## 驗收標準（草案）

- **AC1**：在階段一的量測 bot 加上「有 7 台對手」的情境。Easy、Normal、Hard 三種難度下，玩家每分鐘拿到的 NITRO 和 BOOST 開啟比例，都不低於階段一沒有對手時的 95%。
- **AC2**：Normal 和 Hard 難度下，對手每場平均放 NITRO 的次數比現況多。具體門檻在開工前跟使用者確認。
- **AC3**：Easy 難度的比賽行為跟現況 bit-for-bit 相同，用 deterministic replay 測試鎖住。
- **AC4**：所有計時紀錄都要再升一個版本鍵，沿用階段一的 `record-layout.ts` 機制，舊紀錄標示「舊版配置」。
- **AC5**：重生的光圈和道具要沿用共用的 geometry／material 或 instancing，十張圖的 draw call 不能增加，也不能調高 CI 的 rendering budget。

## 開工前要問使用者的事

- 選「重生」還是「每台車各一份」。
- Hard 難度要多兇：對手每場多放幾次 NITRO。
- Easy 難度是否真的完全不讓對手吃，還是給極少量。
- 這是不是一個新的難度選項或新模式，還是直接改現有的 Normal／Hard。

## 不做的事

- 不做卡丁車式的攻擊道具（丟東西打其他車），那是另一種玩法。
- 只改經典競速，不動世界巡迴、計時賽等其他模式，除非使用者另外同意。
