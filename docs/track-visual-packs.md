# Track visual packs and zero-black-frame loading

Each classic playable or Coming Soon track is registered in `src/track-asset-packs.ts` with its own independently bumped semantic version. These are **optional visual downloads**, not standalone offline playable map binaries. Compiled track physics, code and race rules still ship with the application. A version bump to a map's art must change only that map's `TRACK_PACK_VERSIONS` entry; tests ensure every playable and preview card has an entry. Coming Soon packs include only illustration/route preview art: a downloaded preview never unlocks START or implies a race runtime. Do not change simulation `layoutVersion` merely to update art.

Assets are derived from the existing model, material, sky and sea manifests. SHA-256 from those manifests is used as a content-addressed cache key and verified on download. HDRI/teaser files without published checksums use the map pack version; bump it when changing those files. The file signature is included in the pack receipt, so changing a registered asset invalidates a receipt even before a manual semantic version bump.

The `public/track-asset-sw.js` service worker only intercepts same-origin `models/`, `materials/`, `environments/`, and `track-teasers/` GET requests under the deployment scope. It checks the current Cache Storage index, returns a verified cached response when present, and otherwise uses the original network request. The download fetch uses a distinct query parameter to bypass the worker. Assets never bypass the existing Three.js asset loader, decoder, quality gates, or shader warmup.

A track's `ready` status requires the matching pack receipt, every referenced cache response, and every active index pointer. Cache eviction, failed checksum, interrupted download or newly published map assets must never appear as `ready`. Downloaded assets are still subject to browser storage quotas and eviction; online play remains available without predownloads. User data, progress and save keys are untouched. Shared filenames/sha reuse the same cached bytes.

Verification: `node --test tests/track-asset-packs.test.js tests/track-pack-store.test.js`; `npm test`; `npm run typecheck`; `npm run build`; browser tests for Coast, Neon, Spiral, orientation, High/Ultra, rapid map changes, forced missing assets, service-worker activation and unchanged countdown gating. Require exact-HEAD CI and real WebGL screenshots before marking release-ready.

## Performance instrumentation

The scene controller starts nonblocking selected-map GLB and KTX2 loads on selection, before START, while retaining the same renderer and existing models. The real first successful Home showcase and race grid frames emit one-shot browser events. `src/track-load-telemetry.ts` records durations to the WebGL canvas as `data-home-load-ms` and `data-race-load-ms` and as bounded User Timing measures named `skyline-track-showcase` / `skyline-track-race`. These are observations, not fabricated performance figures; use matching devices, network and quality tiers before claiming improvements.

The fullscreen fallback uses the selected track teaser and is hidden only after the first finished WebGL frame. The static teaser is not guaranteed to match the exact live camera pose: do not claim photo-perfect frame matching until real 3D screenshots replace those teasers.

## 2026-11-22 compact track-download controls

Each of the 16 cards is a separate selection button plus a sibling 42 CSS-pixel download action with an inline SVG ring. Never nest one button inside another. Selected pack versions stay in the dialog footer; one "Download all" button sequentially installs all nonready maps at the selected graphics tier (including preview-only teaser packs). Shared asset bytes are reused, completed maps are skipped, a failed map does not block the next, and the bulk control cancels via AbortSignal. Ring percentages show **file count**, not byte count. No separate PNG/WebP icon files are generated, to avoid extra download weight.

Shared HDRI files without a published SHA-256 use an explicit `shared-hdri-v1` revision independent of each map's version. Bump this revision if any shared HDRI bytes change, so independently updating map artwork does not invalidate other maps or force redundant HDRI downloads.\n
An already-installed map whose published version or current-tier signature changes must be updated before any race entry, retry, cup recovery, or Daily race; the native modal can be cancelled but not bypassed. First-time noninstalled maps can still race online without a compulsory download. Updates validate all referenced assets and publish a fresh receipt before allowing entry; failed/incomplete updates do not clear the gate.\n

## Concurrent install and cache cleanup

Never start a new track install while the previous unreferenced-cache cleanup is using its receipt snapshot. The store must gate new installations on the outstanding cleanup promise while retaining parallel installs between cleanups. Otherwise freshly verified files and index pointers can be deleted before the next receipt is included in that snapshot. The regression in `tests/track-pack-store.test.js` suspends cleanup and starts a second installation; both packs must remain ready. Do not bypass hash checks, receipt validation or the existing Download All browser gate.
