# AI and Blender 3D asset pipeline (planning rule)

Before any Blender asset, GLB import, texture, loader, compression or asset pipeline work:
1. Read docs/superpowers/specs/3d-visual-fidelity-pipeline-design-v2.md and the corresponding implementation plan and local toolchain preflight.
2. Execute Phase 0 environment checks on the actual Mac and record PASS/FAIL/NOT VERIFIED. Owner reports tools installed; this does NOT establish live Blender MCP transport or loaded global Skills. If environment is unavailable, give owner commands; do not invent a result.
3. Run all Skills/MCP setup from the project root: Three.js Skills to `~/.claude/skills` (shared `~/.claude` repo), `blender-image-to-3d` and Blender MCP in project scope (`.mcp.json`, `.codex/config.toml`), never user-scope MCP. Per-device state (`~/.claude.json` approvals, Blender, `uv`) is redone on each machine — see docs/designs/3d-pipeline/phases/README.md. Never copy user config or credentials to this repository. Respect Claude/Codex scope differences and source audit.
4. Until Three.js is tested at r186.1, installed r180 APIs take priority over r186-targeted Skill examples. Then follow the r180→r186 migration plan. Do not implicitly replace WebGLRenderer with WebGPURenderer/TSL.
5. Require valid licensed source, editable Blender masters, stable named pivots/anchors, glTF manifest, PBR colorspace checks, texture budgets, LOD, asset lifecycle and fallback. Do not move physics, road frames or VFX ports for artistic reasons.
6. 2D icon 3× transparency/margin rules in .claude/rules/raster-artwork.md are separate from 3D mesh and PBR texture resolutions.
7. Record RED→GREEN regression tests, frame p50/p95, shader compile/NaN checks, real desktop/mobile WebGL captures, exact-HEAD full CI and art sign-off. Never call a concept illustration an actual in-game screenshot. The target-look concept board is docs/designs/3d-pipeline/track-profiles/skyline-rush-3d-target-concept-board.jpeg (mood reference only; see its README).
8. No PR, deploy, branch reset, force push or merge into develop/main without owner approval.
9. Repeatable checks across devices use docs/designs/3d-pipeline/phase0-multi-device-acceptance.md (E01–E15, device alias, live MCP evidence, per-device report). Never reuse another device's PASS. Phase 0 runs docs/designs/3d-pipeline/toolchain-environment-preflight.md on the actual Mac.
10. Public repo: per-device reports and device names live only in the `.gitignore`-excluded docs/designs/3d-pipeline/audits/; after a pass, write only the general model (e.g. Mac mini) to the local report and audits/device-status.md. Never commit machine identifiers, paths, serials, MCP configs, raw logs or per-device results.
11. Tooling scope (HARD RULE): Skills may stay global (`~/.claude/skills`, the `threejs-*` set); `blender-image-to-3d` stays in `.claude/skills/`. Every other 3D tool — MCP server, plugin, CLI or npm package — installs only in this project (`.mcp.json` / `.codex/config.toml`, exact-pinned `devDependencies`). Never user-scope MCP or a global npm/uv install; remove any global copy found. Commit no credentials.
12. Three.js r186.1 is the planned target (docs/designs/3d-pipeline/threejs-r180-r186-migration.md). A docs-only pass changes no production renderer, physics or sibling branch.
13. The catalog selects the equipped car's GLB, and the graphics tier selects its LOD. Register every track's detailed appearance in `src/track-look.ts` and share `detailedTrackLook()` for scenery, materials and lighting. Low uses the lightweight scene; Medium and above use the registered appearance. Required scenery attaches and warms before GO; a failed set keeps its fallback. Ignore the old `3d=1`, `look=3d`, and `model=roadster` switches, including on dev servers. The Garage-only `model=probe` diagnostic applies to the Roadster. Guards: `tests/track-look-quality-browser.spec.js`, `tests/rendering-quality.test.js`, `tests/dev-3d-redirect.test.js` and the Roadster and Crimson GT browser specs.
14. Every player car shows at the Roadster's size. Trap (2026-11-13): the Crimson GT GLB, built to its concept's proportions, read clearly smaller than roadster2 on every screen. Fix without touching the GLB, and without a per-car constant: `fitToRoadsterSize` (src/car-display-size.ts) measures every player-car GLB when `dress()` clones it and scales the instance to the procedural Roadster: x to the width, y and z one shared factor (the balance of roof height and length) so wheel spin stays round. Home, race, Garage and Coming Soon all dress through it, so a car shows one size everywhere. Never reintroduce `CARS[car].scale` or hand-tuned sizes. Anything that reads GLB pivots in car space (rear-port VFX, launch-flare `bodyFrame`, the lift jets and their gas) multiplies by the instance scale. Trap (2026-11-14): the scale fit left the lift jets on the unscaled `LIFT_PORTS`, 2.6–2.9 cm off roadster2's thrusters (more on the GT); `dress()` now publishes the instance scale as `car.userData.displayScale` (removed on undress) and `effects.js` `liftPort()` multiplies by it, guarded by tests/effects.test.js (*scaled thrusters*), tests/garage-model-rig.test.js (*display scale*) and tests/hero-roadster-race-browser.spec.js (ports). Guards: tests/car-display-size.test.js (GLBs of any size, every host) and tests/crimson-gt-model.test.js (shipped GLBs vs roadster2 within 3%).
15. A visible sky dome never puts its horizon over the bloom threshold. Trap (2026-11-15): Neon reused Coast's dome gain rule (90th percentile of the 0-40 degree band = bloom threshold); a city panorama's horizon glow (the rain grade's veil) then sat at 1.15x to 1.35x the threshold, and over the canal, with no building in front of the dome, the whole horizon bloomed into a white haze. A city panorama sets `sky.gain` from its measured `sky.horizon` (src/coast-lighting.ts); a new sky checks the horizon against the threshold before look-dev. Guard: tests/neon-lighting.test.js (*the dome horizon never reaches the bloom*).
16. A city panorama's near floodlit facades never fill a driven heading's sky or aim its key light. Trap (2026-11-16): Neon's `shanghai_bund` has its embankment buildings (lon -180..-84, up to 43 degrees) at about 8x the rest of the sky, and the harbour drives straight at them: a wall of blurred yellow buildings on the dome, and a key light measured on the map (90% of it that wall) that became a sun at 27-31 degrees straight down the heading, whose specular whited out the wet road and the car (road-ahead mean 210/255, 1.3% clipped). Bloom, the env map, the mirror and the dome were ablated and ruled out. The fix is in the asset build, not the runtime: `FILL` (assets-src/neon-sky/build.py) replaces the wedge on the domes with shifted whole columns of the far skyline, the key is aimed from the filled sky at the same road irradiance, and the 1k maps are filled too (item 18). Never yaw the sky or lower a gain to hide a wall. A new panorama measures `sky.bandByLon` and `key.elevationDeg` before look-dev. Guards: tests/neon-sky-manifest.test.js (*no heading's sky is a floodlit wall*, *the key light is not the floodlit wall*).
17. A sky dome's sign soften targets the signs, never the whole band. Trap (2026-11-16): Neon's `SOFTEN` blurred every texel 0..22 degrees to hide LED text, halving the far skyline's gradient, so High looked soft at a 1:1 texel ratio and 8K could not fix it. Mask by chroma and peak. Guard: `sky.sharpness >= 0.7 x sky.sourceSharpness`, tests/neon-sky-manifest.test.js (*only LED facades are softened*).
18. A fill applied to the dome is applied to the 1k environment map too, with the removed light returned so the horizontal irradiance holds. Trap (2026-11-16): the domes hid Neon's floodlit wall but the 1k map kept it (item 16's first fix); the wet road mirrors the 1k map, so the rain harbour road read tan. Fill copies whole columns of generic skyline only, at a height that cannot repeat a landmark within one 90-degree view. Guards: tests/neon-sky-manifest.test.js (*the 1k map's sky is not a floodlit wall either*, *keeps the download's horizontal irradiance*).
19. A landmark placed beside the road is checked from the driver's seat, not only on the plan: its bearing from the approach (about 200 m out) and while passing must stay inside the view (the plan test computes it from `classicRoadRoute`). Trap (2026-11-16): the oldtown clock tower stood 45 m out at the square's middle, 51 degrees off the heading alongside, and slid out of view as the driver reached it. Guard: tests/neon-scenery-plan.test.js (*the clock tower on the square*).
20. On a street-grid lap the key light sits on a street axis, never over the car's shoulder. Trap (2026-11-16): item 16's fix aimed Neon's night key from the filled sky (elevation 58 degrees) and it landed 119 degrees off the harbour heading; the player car's sloped rear deck mirrored it into the chase camera as a white bar the width of the car for the whole straight (1300 to 1600 px of luma >= 235 at 1280x720, left lanes). The band is a key 105 to 150 degrees off the heading, on either side, under about 76 degrees of elevation. The first diagnosis ("the straight heads toward the key") had the angle wrong, and a diagonal key only moves the bar: the lap drives all four street directions, so it stands 135 degrees off two of them. Mechanism: `on_street_axis` (assets-src/neon-sky/build.py) turns the key about the vertical onto the street axis nearest its measured azimuth, elevation and intensity kept, and `key.filled` keeps the measurement; no texture changes. Rain night's key (76.7 degrees) measured clean and is not turned. A new key, car body or lap direction re-runs the per-straight lane sweep (every long straight, both outer lanes) before look-dev. Guards: tests/neon-lighting.test.js (*the key light never stands over the car's shoulder on a long straight*), tests/neon-sky-manifest.test.js (*night's is turned onto the nearest street axis*).
21. A hero landmark's own dressing never stands on the driver's sightline to it, and its lamps reach the bloom. Trap (2026-11-16): the plaza sculpture passed item 19's bearing check and still read as a dark shape until the car was alongside: the court's near tree row and the last pavement tree stood on the line from every lane to the plinth, hiding the only lit part, and at the landmark kit's strength (1.5) its one lamp, the violet rings (linear luminance 0.208), sat at a third of the bloom threshold. Mechanism: the near row splays back from the street and the pavement trees stop 40 m before the court (src/neon-scenery-plan.ts); `PIECE_EMISSIVE` (src/neon-scenery.ts) gives a hero piece its own strength on a copy of the kit material the layer owns: no draw added, no other piece changed. A kit-wide strength is set for the kit's brightest lamp; a piece whose only lamp is dimmer is checked on its own. Guards: tests/neon-scenery-plan.test.js (*the sculpture shows on the approach*), tests/neon-scenery.test.js (*the sculpture has its own emissive strength*).
22. An emissive strength is judged by lit area as well as by peak texel. Trap (2026-11-16): the city kit's strength (1.7) keeps its brightest texel within twice the bloom threshold, which holds for a tube or a blade sign; the street screen (`billboard_a`, 58 m2 of lit texels, its graphics at 1.55x the threshold) bloomed over its own picture where it stands beside the car, and read near-white (28% of its pixels white on the straight after the rail tunnel, 9% after the fix). Mechanism: the screen has its own strength in `PIECE_EMISSIVE` (1.2: graphics just over the bloom), on a copy of the kit material; no draw added, the wall screens and every other piece unchanged. A new large lit surface (screen, lit facade, floodlit wall) is captured from the nearest point the driver passes it, not only from down the street. Guard: tests/neon-scenery.test.js (*the street screen has its own emissive strength*).
23. A piece's baked night light is checked up its height and against its paint, not only by its median. Trap (2026-11-16): two pieces passed their `lit` floors and still read dark. The plaza sculpture's only baked light was its rings' spill, which ended under the fan's upper half (median runtime emissive 0.0 above half the piece's height): dark steel blades over a lit plinth. The cargo ship's funnel was hull navy beside a white deckhouse (0.023 against 0.46), and no flood lifts dark paint to a white wall's level without running the white boxes beside it into the roll-off. Mechanism: `FILL` (assets-src/neon-landmarks/build/lighting.py) bakes a piece's own work lights into that piece's texels only, never dimming one, up to a stored ceiling set for the piece's `PIECE_EMISSIVE` strength (ceiling x strength under the bloom threshold), so the other pieces of the kit keep their bake and no draw, light or material is added; a part that must read light at night is painted light (the funnel is painted plate, the ship's `crane` surface) before any flood is raised. A new hero piece reads `lit_upper` and `lit_end` in `contract.json`, and a kit's emissive pin moves only with a confinement check (changed texels on other pieces' triangles: 0). Guards: tests/neon-landmarks-glb.test.js (*the plaza sculpture carries its violet up the blades*, *the cargo ship shows its hull, stern and funnel*).
24. A second colourway of one painted cell is not a second design. Trap (2026-11-16): Neon's underpass straight alternated `store_glass` and `store_violet` podiums, both painted by `storefront()`: one flat-headed three-bay shopfront in two colours down both sides (bay shape 0.772 of the run open at eye height and 0.789 under the fascia on every block kind), which street dressing per kind did not hide. Mechanism: `arcade()` (assets-src/neon-city/build/cells.py) paints a round-arched 4 m bay for `block_retail_a`; `buildings.PODIUM` names each module's podium cell and build.py measures its bay shape into `summary.json`. A variant is judged by a measured shape, not by its cell name or tint. Before adding a cell, run the shelf packing: the city atlas is 98.2% full (2012 of 2048 px), a 256 x 288 bay fits a row's spare width and a 768 x 288 shopfront overflows by 28 px. A painter that takes no random numbers leaves the shared stream, and every reviewed cell, as it was. Guard: tests/neon-scenery-plan.test.js (*no three plots in a row on either side share one podium bay shape*).
25. A wheel arch is cut from a smooth body, never by clipping the lofted sections. Trap (2026-11-16): the Crimson GT clipped every cross-section at the arch height (`clip_profile`), which sheared the quads at each arch end and dropped the character line over the wheel, so every fender stepped 4.5 cm in (lip 1.100 m vs body 1.165 m) and read as a crash dent. Mechanism: the loft flares its shoulder to full width over each wheel (`flare`, assets-src/crimson-gt/build/gt_body.py) on an even station grid, and `cut_arches` (gt_parts.py) boolean-subtracts one cylinder per wheel (EXACT solver). A new car follows the same order: smooth loft first, then cut. Guard: tests/crimson-gt-model.test.js (*every fender is flared to full width over its arch*).
26. A shut line is never baked by a straight box across a curved or scalloped flank, and a panel laid on the body samples the body's own stations. Trap (2026-11-17): the Crimson GT bake cut 8 mm door boxes at z -0.62 and +0.50 into the body HIGH copy; on the scalloped flank each box only grazed the surface, so the coat normal carried broken 30-90 degree slashes that read as vertical cracks on both sides. The side intake, corner intakes and rockers (`patch`, gt_body.py) were lofted on a coarser z grid than the body, so the convex flank poked through their chords: a sawtooth edge and a ragged top rear. Mechanism: GROOVES (assets-src/crimson-gt/bake.py) keeps only the hood seam; `patch(z0, z1, ...)` puts its sections on `stations()`. A new shut line is modelled in the LOW mesh or follows the surface; a straight box goes only on a near-flat panel. Guard: tests/crimson-gt-model.test.js (*the body flanks carry no crack in the baked coat normal*: texels tilted over 25 degrees on 3+ rows of one 2 cm z band, high and low LOD).
27. A body crease is never one section point, and no fold may cross the bake bevel's 30 degree limit or the 50 degree sharp split along its length. Trap (2026-11-17): the Crimson GT scallop was one `side_profile` point, so it lofted into a one-edge fold that went from 14 to 68 degrees along the door; the bevelled bake copy rounded it on one stretch and not the next, the sharp split cut in mid-door, and the narrow 12 mm bevel drew texel stairs in the 1024 atlas, so the highlight stepped. Mechanism: `gt_body.py` samples the cove at `COVE_LO`/`COVE_UP` with a raised-cosine inset (visible flank folds at or under 27 degrees); a panel laid on a deep cove copies its folds, so `side_intake` has 12 rows (4 let the flank poke 15 mm through its top) and is left out of `bake.py` `BEVELLED` (its face sits on folds right at 30 degrees). Guard: `tests/crimson-gt-model.test.js` "no visible flank fold reaches the bake bevel limit" measures welded dihedrals of the shipped body and the intake atlas texels on both LODs; RED on the old GLB (54.7 degrees).
28. A roadside prop's side and position come from its absolute distance index, never from its slot in a moving window. Trap (2026-11-18): `world.js` took each street lamp's side from `i % 2`, its slot in the 24-lamp window, so every 60 m all the lamps on every classic track changed sides; the Coast GLB lamp posts, placed by absolute distance, then stood opposite their lamp heads on every other 60 m stretch. Mechanism: `d / 60 % 2` in `world.js`, and `coastChunkPlan` (`src/coast-scenery-glb.ts`) puts `lamp_post` on the same parity, its arm turned to the road on both sides (the right-hand guard rail gets the same half turn). A prop that replaces a procedural one hides it through `material.visible` only while the replacement is drawn, so Low, other tracks and a failed load keep it (`poles` in `src/coast-assets.ts`). Guards: `tests/coast-assets.test.js` (*world.js hands ... lamp posts to the Coast assets*, *the box lamp posts leave Coast*), `tests/coast-scenery-glb.test.js` (*placed pieces sit where the chunk plan puts them*) and `tests/coast-scenery-browser.spec.js` (*stands a modelled lamp post under every lamp head*), which samples each 20 m with no retry: a poll passes on the old code as soon as the car drives into the next, matching stretch.
29. A scan drawn at far-headland size draws its decimated far node, and a new GLB node reaches every place that lists the nodes. `COAST_FAR_LOD` (`src/coast-scenery-glb.ts`) names the far node of a piece (`cliff_a_far`, `cliff_b_far`: 2,500 triangles for 11,000, same UVs, material and baked maps, so no texture or program is added); `FAR_LODS` in `assets-src/coast-scenery/build.py` builds them, and anything that dresses the cliffs (`src/coast-greenery.ts` `HOSTS`) covers the far nodes too. Trap (2026-11-18): adding `lamp_post` and the far nodes broke three unit fixtures that build a fake coast GLB and one `world.js` call regex nobody had listed; before adding a node, grep `tests/` for `COAST_PIECES`, `fakeGlb` and the node list in `src/model-manifest.ts`. A browser check that reads an instance matrix remembers the node's own dequantization transform: the instance origin is not the pivot and its scale is not the placement scale, so measure a point of the geometry's bounding box or count instances. Guards: `tests/coast-scenery-glb.test.js` (*far headlands draw the decimated far nodes*), `tests/coast-greenery.test.js` (far headland tops) and `tests/coast-scenery-browser.spec.js` (*draw-call cap*: headlands in the far pools, at most one close cliff per chunk).
